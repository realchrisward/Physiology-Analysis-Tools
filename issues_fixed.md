The other six bullet points (beat detection quality on low-amplitude R waves, manual beat addition tool, bad-data-marking refinement, wider viewing window, post-breath false positives, steady-vs-transient bradycardia category, performance with many loaded files) are **not** addressed — see section 3. |
| [#40](https://github.com/realchrisward/Physiology-Analysis-Tools/issues/40) / [#13](https://github.com/realchrisward/Physiology-Analysis-Tools/issues/13) | ECG beat detection performs poorly in some files / algorithm needs improvement | OPEN | **Partially resolved**, two independent fixes: (1) `heartbeat_detection.beatcaller()` gained an opt-in `auto_detect_invert` setting (default `False` — zero behavior change unless enabled) that automatically corrects inverted R-peaks, one of the two causes named directly in #13 ("may also have inverted R peaks"). Uses a 97th-percentile positive-vs-negative peak amplitude comparison (a plain-mean version misfired on real data during testing and was replaced), with a minimum-peak-count guard so it safely no-ops on short/sparse recordings rather than guessing. Verified against all 6 real `.txt` sample files: 100% identical output with the setting off, never incorrectly flips a correctly-oriented signal, and exactly recovers the original beat set from a synthetically-inverted copy of the 2 files with enough peaks to trust the comparison. **Not** tested against an actual inverted `.adicht` file (none available, and `adi-reader` doesn't run on macOS) — the fix operates on the already-extracted signal array regardless of source format, so this is a low residual risk, but it's worth a real-world re-check on Windows. (2) `gather_data()`'s stride-based downsampling — which used to silently skip transient spikes/arrhythmic beats when zoomed out — replaced with min-max downsampling (keeps both the min and max sample per pixel-bin). Confirmed with a synthetic-spike test: the old method's output completely missed a planted spike (max captured value 0.18 vs. the real 5.0); the new method captures it exactly, with a comparable number of rendered points. **Still open / not addressed**: the "large voltage shifts due to movement" / baseline-drift cause named in #13 — that would need a bigger change to the threshold-setting logic (local/rolling threshold instead of one global percentile) and was judged too risky to attempt without a way to test against the actual failing file. |

## 4. Bugs we found in codebase with no corresponding GitHub issue

For completeness — these don't have an open upstream issue tracking them, so they'd need a new issue filed if still open:

- **Bug 12 / Plan Item 11 — FIXED this session.** Absolute-pixel UI layout (53 `geometry` properties vs. 1 layout manager) — window couldn't be resized. Not filed upstream as its own issue, though #41 (scrollbar not full width, closed) was a symptom of the same underlying layout style. Rebuilt `ecg_analysis_tool.ui`'s entire central widget as a nested `QSplitter`/`QVBoxLayout`/`QGridLayout` tree (left file/signal sidebar, center graph + transport controls, right arrhythmia-review panel, bottom status bar), with the graph column getting resize priority. All 53 `objectName`s preserved exactly (verified programmatically — nothing renamed, nothing missing, all widget-specific properties like spinbox min/max intact), so no Python code needed to change for this beyond adding splitter stretch factors. Verified by rendering the window at 3 sizes (700×500 clamped up to the layout's real minimum of 875×573, default 1000×772, and 1400×900) with no clipping or overlap, plus a full functional smoke-test re-run.

- **Bug 10 / Plan Item 16** — No automated tests anywhere in the repo. No open GitHub issue. Still not implemented.
